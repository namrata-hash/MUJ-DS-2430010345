7. TRAINING DATA BALANCING
---------------------------
To reduce the effect of severe class imbalance during model training,
a controlled balanced training pool was created.

Sampling strategy:
- Maximum 10,000 samples per class
- Random state: 42
- Total balanced pool: 80,000 samples
- 10,000 samples for each of the 8 classes

The held-out test set was NOT artificially balanced. It was retained in
its original distribution so that model performance could be evaluated
under a realistic class distribution.

10. PREPROCESSING PIPELINE
---------------------------
The preprocessing procedure is:

1. Load the CICIoT2023 Parquet training and test files.
2. Inspect the data and class distribution.
3. Remove exact duplicate rows from the training data.
4. Create a balanced training pool using up to 10,000 samples per class.
5. Remove attack_class, Label and label from the feature matrix.
6. Retain the 39 numerical network-flow features.
7. Encode the eight grouped attack classes.
8. Perform a stratified 80/20 training-validation split.
9. Fit StandardScaler only on the training data.
10. Apply the same fitted scaler to validation and test data.

14. IMPORTANT INTERPRETATION NOTE
----------------------------------
The training data is balanced only for model fitting. The original
imbalanced test set is retained for final evaluation.

Therefore, macro-averaged metrics such as Macro Precision, Macro Recall,
Macro F1 and Macro Specificity are important because they provide
class-aware evaluation and reduce the risk of judging performance only
from the dominant DDoS class.

Published CICIoT2023 results should also be compared carefully because
different studies may use different class definitions, sampling
strategies, train-test splits, preprocessing methods and evaluation
protocols.
